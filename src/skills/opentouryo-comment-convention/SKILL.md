# コメント／ファイルヘッダ規則

> 📋 **コピー元テンプレート**：`references/snippets.md`（C# / VB のファイルヘッダ全文。実装時はここから写す）。

出典＝実サンプル（`Samples`／`Samples4NetCore` の `.cs`・`root/programs/VB` の `.vb`）で裏取り。

## 原則

1. **コード内のコメントは言語仕様に従って書く**（C#＝`//` とインライン、クラス・メソッドは `/// <summary>` XML doc／
   VB＝`'` と `''' <summary>`）。
2. **新規のコードファイル（`.cs` / `.vb`）の先頭に、ファイルヘッダを「その言語のコメント」として埋め込む。** 2ブロック構成：
   - **① 所属機能名バナー**（そのファイルのレイヤ P/B/D を示す）。
   - **② クラス情報ブロック**（`クラス名` / `クラス日本語名` / `作成日時` / `作成者` / `更新履歴` の表）。

## ファイルヘッダの形（C# ＝ `//*`）

コメント接頭辞は言語で変える（**C#＝`//*`／VB＝`'*`**）。**バナー行は接頭辞＋`*`×82**。全文と VB 版は `references/snippets.md`。

```csharp
//**********************************************************************************  ← * ×82
//* フレームワーク・テストクラス（Ｂ層）        ← 所属機能名（レイヤ）
//**********************************************************************************

//**********************************************************************************
//* クラス名        ：（クラス名）
//* クラス日本語名  ：（日本語名）
//*
//* 作成日時        ：YYYY/MM/DD
//* 作成者          ：（作成者）
//* 更新履歴        ：
//*
//*  日時        更新者            内容
//*  ----------  ----------------  -------------------------------------------------
//*  YYYY/MM/DD  XXXX YYYY         ZZZZZZZZZZ
//**********************************************************************************
```

## 細部

- **項目名は全角で、`：` を桁揃え**する（サンプルの整列に合わせる：`クラス名`＝全角4字＋空白／`クラス日本語名`＝7字＋空白 …）。
- **更新履歴の表**：`日時`（`----------` 10桁）／`更新者`（`----------------` 16桁）／`内容`。改修のたびに**行を足して追記**する（消さない）。
- **ファイルは UTF-8 BOM 付き（★体裁でなく機能要件）。** BOM が無い UTF-8 を既定コードページ（日本語環境＝Shift-JIS）で
  解釈され、**日本語コメント／文字列リテラルが文字化けして壊れる**ことがある。**対象は `.cs`/`.vb` だけでなく、
  実行時にコンパイルされるビュー `.cshtml`/`.aspx`/`.master` も**（エージェントのファイル書き込みは通常 BOM 無しなので確実に踏む）。
  → **新規に作った／書き直したこれらのファイルは書き込み後に BOM を後付けする**（先頭3バイト `EF BB BF` を確認。例：`od -An -tx1 -N3 <file>`）。
  **★ 実害が確認されているのは「実行時コンパイルされるビュー」、特に net48 MVC**——`Web.config` に `<globalization fileEncoding>` が無いと
  ランタイム Razor が Shift-JIS 誤読し、CP932 の2バイト目が直後の ASCII（`</button>` の `<` 等）を食ってタグを壊す＝**文字化け＝ボタンも動かない**
  （ビルドも `aspnet_compiler` も素通り。net48 MVC の詳細は `opentouryo-layer-p-mvc`／WebForms は `<globalization fileEncoding="utf-8">` 同梱で安全）。
  `.cs` も規約として BOM を付ける（環境により早期コンパイラが既定コードページで解釈しうる＝防御的に付与。`opentouryo-base2-customize` の BOM 保持と同旨）。
  **★ ファイルを書き直したら BOM が落ちていないか毎回確認する**（エディタが BOM 無しで書き戻すため、一度付けても再編集で外れる）。
- **`.aspx` / `.master` などマークアップにはバナーを付けない**（`<%@ Page … %>` で始まる）。コメントは `<!-- -->`／`<%-- --%>`。ただし**コードビハインド `.aspx.cs` には付ける**。
- **自動生成ファイル（自動生成 Dao 等）はツールがヘッダを付ける**ので手で足さない・書き換えない（`opentouryo-dao-generated`）。

## インラインの節区切りコメント（`↓` / `↑`）＝ UOC（User Own Coding）の範囲

**スケルトン（テンプレート）コードの中で、開発者が自分のコードを書く範囲＝UOC（User Own Coding）** を、
開始 `// ↓〈ラベル〉----…` と終了 `// ↑〈ラベル〉----…` の**対**で囲む。**処理を変更するときの修正範囲がここ**で、
外側のスケルトン（メソッドの骨格・前後処理）は原則そのまま。ラベルは**その UOC が何をするか**を示す（`LayerD.cs`・`LayerB.cs`・`Bat_sample/Program.cs` で多数使用）：

| 文脈 | ラベル | UOC で書く内容 |
| --- | --- | --- |
| D層（個別Dao） | **`DBアクセス`** | `SetSqlByFile2` / `SetParameter` / `ExecXxx` の一連 |
| B層（業務クラス） | **`業務処理`** | 業務ロジックの本体 |
| 呼び出し側（P層／バッチ `Program`） | **`B層実行：〈説明〉`** | B層呼び出し（`CallController.Invoke` / `DoBusinessLogic`）。`：` の後に**何を実行するかを自由記述**（例：`主キー値を全て検索(ORDER BY 主キー)`） |

- 開始は `↓`、終了は `↑`。**ラベルの後をダッシュで埋めて行の幅を揃える**（`DBアクセス`/`業務処理` など短いラベルは `-`×53。`B層実行：…` のように長いラベルはダッシュを減らす）。コードの**インデントに合わせる**。
- **`↓`〜`↑` の外はスケルトン＝原則そのまま。** 処理変更は `↓`〜`↑` の中（UOC）で行い、修正範囲を示す。コード例は `references/snippets.md`。

## やってはいけないこと

- **ファイルヘッダを別言語のコメント形式で書く**（C# に `'*`、VB に `//*` 等）— 言語の接頭辞に合わせる。
- **`.aspx` 等マークアップにコード用バナーを付ける** — マークアップには不要。
- **更新履歴を消す／桁揃えを崩す** — 行を足して追記し、整列を保つ。
- **クラス・メソッドの `/// <summary>`（VB は `''' <summary>`）を省く** — 言語標準の doc コメントを付ける。
