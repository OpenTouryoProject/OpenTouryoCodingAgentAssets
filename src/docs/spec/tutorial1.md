# 仕様：Shippers 管理画面（チュートリアル1）

> これは **spec → plan → 実装** の流れを学ぶためのサンプル仕様です。
> 「何を作るか（要件・受入条件）」だけを書き、「どう作るか」は `docs/plan/tutorial1.md` に分けます。

## 目的

OpenTouryo のサンプル DB にある **Shippers（配送業者）テーブル**に対して、
一覧表示・検索・登録・更新・削除ができる 1 画面を実装する。

## 前提

- `opentouryo-project-setup`（必要なら `-db` の Docker サンプル DB）で**構築済みのプロジェクト**があること。
- P層の処理方式は **ASP.NET Web Forms**、ランタイムは **net48**（既存プロジェクトが MVC / net10.0 ならそれに合わせて読み替える）。
- 対象テーブル **Shippers** の列は次の3つ（サンプル DB のとおり）。**タイムスタンプ列は無い。**

  | 列 | 種別 | 備考 |
  | --- | --- | --- |
  | `ShipperID` | 主キー | 自動採番（INSERT では指定しない） |
  | `CompanyName` | 文字列 | 必須 |
  | `Phone` | 文字列 | 任意 |

## スコープ（作るもの）

1. **一覧表示**：Shippers を一覧で表示する。
2. **検索**：`CompanyName` の部分一致で絞り込む（空なら全件）。
3. **登録**：`CompanyName` / `Phone` を入力して 1 件追加する（`ShipperID` は自動採番）。
4. **更新**：一覧から 1 件選び、`CompanyName` / `Phone` を変更して保存する。
5. **削除**：一覧から 1 件選んで削除する。

## 機能要件

- 検索条件 `CompanyName` は**ユーザ入力をパラメタで渡す**（SQL 文字列に直接埋め込まない）。
- 登録・更新・削除は**1 つのトランザクション**で処理し、失敗時はロールバックする。
- 更新・削除で**対象が 0 件だった場合**（他者が先に削除した等）は、やり直し可能なエラーとして扱い、
  ユーザにメッセージを返す（画面はエラーで落とさない）。
- 入力チェック（`CompanyName` 未入力など）はやり直し可能なエラーとして扱う。

## 非機能・制約

- **層の責務を守る**：画面（P層）に業務ロジックや SQL を書かない。トランザクション境界は B層。D層は SQL 実行のみ。
- P層 → B層は所定の経路（サービス論理名で呼ぶ）で呼び出す。B層 → D層は接続を渡して Dao を生成する。
- 例外方針は OpenTouryo の規約に従う（やり直し可能＝業務例外、不可＝システム例外。業務例外は呼び出し側で `catch` しない）。

## 受入条件（チェックできる形で）

- [ ] 一覧に Shippers の全行が表示される。
- [ ] `CompanyName` に文字列を入れて検索すると、部分一致した行だけが表示される。空で検索すると全件に戻る。
- [ ] 登録すると新しい `ShipperID` が採番され、一覧に増える。
- [ ] 更新すると該当行の `CompanyName` / `Phone` が変わる。
- [ ] 削除すると該当行が一覧から消える。
- [ ] 存在しない行を更新・削除しようとすると、エラーで落ちずにメッセージが返る（更新件数 0 の検知）。
- [ ] `CompanyName` 未入力で登録・更新すると、やり直し可能なエラーとしてメッセージが返る。

## スコープ外（発展課題）

- **タイムスタンプによる楽観排他**：Shippers にはタイムスタンプ列が無いため本課題では扱わない。
  タイムスタンプ列を持つテーブルなら、自動生成 Dao がタイムスタンプ アンマッチ（更新件数 0）で楽観排他を行う。
- 明細グリッドの一括更新（`DataTable` の RowState を使ったバッチ更新）は別課題とする。
- 認証・認可、ページング、入力値の高度なバリデーション。
