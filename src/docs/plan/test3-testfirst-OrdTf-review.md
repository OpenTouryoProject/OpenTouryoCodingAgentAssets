# テスト先行：レビューの観点（受注一覧 OrdTf）

**レビュー役が使う**（司令役が渡す）。段 1（テスト仕様）・段 2（Red）・段 4（Green）を承認する前に、ここと突き合わせる。
**実装役には読ませない**（読むと、仕様からテストを起こす力を確かめられない）。

どの対象にも共通の観点は [cmn-testfirst-review.md](./cmn-testfirst-review.md)（両方を使う）。

仕様の出どころは [spec/test3-testfirst-OrdTf.md](../spec/test3-testfirst-OrdTf.md)。段 1 のテスト仕様に、次が入っているか。

| 種類 | 観点 | 根拠 | 入っているべきケース（例） |
| --- | --- | --- | --- |
| B層 | 抽出条件 | `EV-ORD-102` 手順 2 | 顧客・担当者・受注日開始（当日を含む）・受注日終了（当日を含む）のそれぞれ。**未指定の条件は絞らない** |
| B層 | 出荷状況・納期遅延 | `EV-ORD-102` 手順 2、`ORD-T2`・`ORD-T7` | 未出荷・出荷済・すべて。納期遅延は、未出荷で `RequiredDate < 当日`、出荷済で `ShippedDate > RequiredDate`、**`RequiredDate` が NULL は遅延にしない** |
| B層 | 状況の判定 | 「共通の処理」状況の判定 | 行ごとの「未出荷」「出荷済」「納期遅延」 |
| B層 | 並べ替えの既定 | `EV-ORD-101` 手順 3、`SC-ORD-01-I06` | 受注日の降順、**同日は受注 ID の降順** |
| B層 | 合計金額 | 「共通の処理」受注検索クエリ、`DEC-CMN-02`・`03` | `Σ(UnitPrice × (1 - Discount) × Quantity) + Freight`。明細 0 件の小計は 0、Freight が NULL は 0 |
| B層 | 0 件 | `EV-ORD-101` 手順 7 | エラーにしない |
| B層 | 日付の前後関係 | `EV-ORD-102` 検証内容（`VAL-DATE`）、`DEC-CMN-01` | 開始 > 終了は業務エラー。メッセージは仕様の文言（`ErrorMessage`） |
| B層 | 結合の NULL | `SC-ORD-01-I06` 列 2・3・7 | 顧客・担当者・配送業者が NULL の受注も出る（外部結合） |
| B層 | 選択肢 | 「共通の処理」選択肢の構築、`I01`・`I02` | 顧客は会社名の昇順（値 `CustomerID`）、担当者は姓・名の昇順（表示 `姓 名`。姓が同じなら名で並ぶ） |
| B層 | ページ | `EV-ORD-104` 手順 2・3、`I06`〜`I08` | 1 ページ 20 件、2 ページ目が 21 件目から、最終ページの件数、総件数はページによらず全体 |
| E2E | ボタンの活性の境界 | `B05` の活性条件 | 1 ページ目で先頭・前が非活性、最終ページで次・末尾が非活性、**1 ページしか無い・0 件のときは全部非活性**（`DEC-ORD-02`） |
| E2E | 移動とページ情報 | `EV-ORD-104` 手順 3、`I08` | 次・前・先頭・末尾の後の「n / m ページ」 |
| E2E | 条件を保つ | `EV-ORD-104` 入力、`DEC-ORD-04` | 絞ってから次へ → 絞った件数のまま。入力欄だけ変えて次へ → 最後に検索した条件のまま |
| E2E | メッセージの種類 | `HLD/Common.md` 4 節（メッセージ表示）、`EV-ORD-101` 手順 7 | 0 件の知らせはエラーの見た目でない、前後関係の違反はエラーの見た目（文言だけでなく区別も確かめる） |
| E2E | 検証エラーの直後 | `EV-ORD-102` 手順 1、`DEC-ORD-03` | 開始 > 終了・日付として解釈できない入力の両方で、直前の一覧が残り、入力欄は入力した値のまま、次へは直前の条件 |
| 共通 | ボタンの id | `B05`、`DEC-ORD-05` | 先頭・前・次・末尾の 4 つの id がテスト仕様で決まっている（ページ番号の直接選択は作らない） |
